# iterate 스킬 / Apply user-test feedback (1–2 items)

다른 팀의 사용자 테스트 피드백을 받아, **가장 임팩트 큰 1~2개만** 빠르게 반영한다.
시간 안에 다시 라이브로 보여 주는 것이 목표이므로 **범위를 넓히지 않는다.**

## 단계 (Steps)
1. 현재 `index.html`을 읽는다.
2. 사용자가 준 피드백에서 **임팩트가 큰 1~2개만** 고른다. 각 선택 이유를 한 줄로 적고, 나머지는 "다음에"로 미룬다.
3. 고른 항목만 **최소 변경**으로 반영한다. (디자인 규칙 유지, 새 기능 추가로 범위를 키우지 말 것)
4. **지금 브랜치(보통 `integration`)**에 커밋·push한다.
5. 무엇을 바꿨고 무엇을 미뤘는지 요약한다. (Vercel이 연결돼 있으면 push가 곧 같은 URL로 재배포)

## 공통 디자인 규칙 (Design rules)
- 외부 라이브러리·CDN·웹폰트 **금지**. 시스템 폰트만: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`
- 색: 배경 `#f6f7fb`, 카드 `#ffffff`, 강조 `#4f46e5`(남용 금지), 본문 `#1f2433`, 보조 `#6b7280`, 테두리 `#e5e7eb`
- 모서리 12~16px, 부드러운 그림자, 넉넉한 여백, 모바일·데스크톱 **반응형**
- **한국어 UI**, 버튼·입력은 실제로 동작
- **단일 자기완결형 HTML 파일**(CSS·JS 인라인), 외부 의존성 없음
